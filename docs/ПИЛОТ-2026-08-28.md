# Пилот в клубе — 28.08.2026 (два компьютера)

Схема: **ПК-1** — сервер + стойка (Docker: Postgres + backend, админка в
браузере). **ПК-2** — гостевой (киоск Shell1448 + агент). Телефоны гостей —
по Wi-Fi клуба к ПК-1. Клубная база — чистая, новая: демо-стенд в облаке и
домашний стек тут ни при чём.

Всё, что ниже — команды для Windows. Длинные команды не набирай руками,
копируй отсюда.

применяются сами; в облаке этот путь сегодня прошёл целиком, но проверь и
докерный вариант):

## 1. ПК-1 — сервер + стойка (~40 мин, больше всего ждать Docker)

1. Поставь **Docker Desktop** (с флешки). Согласись на WSL2, перезагрузись.
   В настройках Docker Desktop включи «Start Docker Desktop when you sign in».
2. Распакуй `1448-src.zip` в `C:\1448`, положи туда же `.env.club`,
   поставь в нём `PUBLISH_PORT=8080`.
3. Запусти стек:
   ```
   cd C:\1448
   docker compose -p 1448club -f docker-compose.club.yml --env-file .env.club up -d --build
   ```
   Первый запуск качает образы — до 10 минут. Миграции применятся сами.
4. Проверка: http://localhost:8080/health → `ok`.
5. **Файрвол** (PowerShell от администратора):
   ```
   netsh advfirewall firewall add rule name="1448 backend" dir=in action=allow protocol=TCP localport=8080
   ```
6. **IP-адрес ПК-1**: `ipconfig` → запиши IPv4 (например `192.168.1.50`).
   Попроси у владельца DHCP-резервацию этого адреса на роутере (или задай
   статику), иначе после перезагрузки роутера IP может смениться — и киоск
   с телефонами потеряют сервер.
7. **Первые учётки клуба**: открой http://localhost:8080/register и
   зарегистрируй владельца и админа (реальные ники/пароли, не демошные!).
   Потом выдай роли (одной строкой, подставь ники):
   ```
   docker compose -p 1448club -f docker-compose.club.yml --env-file .env.club exec postgres psql -U club1448 -d 1448_db -c "UPDATE users SET role='owner' WHERE nickname='НИК_ВЛАДЕЛЬЦА';"
   docker compose -p 1448club -f docker-compose.club.yml --env-file .env.club exec postgres psql -U club1448 -d 1448_db -c "UPDATE users SET role='admin' WHERE nickname='НИК_АДМИНА';"
   ```
8. **Клуб и зал**: клуб заведи одной командой (имя/адрес/тариф поправь):
   ```
   docker compose -p 1448club -f docker-compose.club.yml --env-file .env.club exec postgres psql -U club1448 -d 1448_db -c "INSERT INTO clubs (id, name, address, base_rate_pln, rtp_modifier, is_active) VALUES (uuid_generate_v4(), 'НАЗВАНИЕ КЛУБА', 'АДРЕС', 23.00, 1.00, TRUE);"
   ```
   ПК создай в админке (http://localhost:8080/admin, вход владельцем) —
   конструктор зала: добавь `PC-01` (это будет ПК-2) и сколько хочешь ещё.
9. **UUID гостевого ПК** (понадобится на ПК-2):
   ```
   docker compose -p 1448club -f docker-compose.club.yml --env-file .env.club exec postgres psql -U club1448 -d 1448_db -c "SELECT id, name FROM computers;"
   ```
   Запиши id того ПК, которым будет ПК-2.

Админка стойки с этого момента — http://localhost:8080/admin на ПК-1.

## 2. ПК-2 — гостевой киоск (~30 мин)

1. **WebView2**: на Win11 уже есть; на Win10 поставь Evergreen Runtime
   (https://developer.microsoft.com/microsoft-edge/webview2/).
2. Скопируй с флешки папку `Shell1448` в `C:\Shell1448`.
3. **`C:\Shell1448\agent\agent.json`** (агент обязателен: он отдаёт экрану
   computer_id, запускает игры, держит связь с сервером):
   ```json
   {
     "backend_ws": "ws://192.168.1.50:8080/api/v1/ws/shell",
     "computer_id": "UUID_ИЗ_ШАГА_1.9",
     "listen": "127.0.0.1:1448",
     "catalog_url": "http://192.168.1.50:8080/api/v1/catalog",
     "lock_action": "none",
     "kiosk_url": "",
     "cleanup": { "enabled": false, "dry_run": true },
     "apps": {}
   }
   ```
   (`apps` заполнишь локальными путями игр этого ПК по образцу
   `backend\cmd\agent\agent.example.json`; на пилоте можно начать пустым.)
4. **`C:\Shell1448\App\shell.json`**:
   ```json
   {
     "shell_url": "file:///C:/Shell1448/App/web/shell.html?api=http://192.168.1.50:8080/api/v1",
     "catalog_url": "http://192.168.1.50:8080/api/v1/catalog",
     "kiosk_keys": true,
     "exit_password": "СВОЙ_ПАРОЛЬ_ВЫХОДА"
   }
   ```
   `?api=` в адресе — это сегодняшняя правка shell.html: экран запомнит
   адрес сервера сам, DevTools не нужны. Провериться можно по индикатору
   сервера на экране киоска — там должен быть адрес ПК-1, не localhost.
5. **Порядок запуска**: сначала агент (`agent\shell-agent.exe`), потом киоск
   (`App\Shell1448.App.exe`). Если Windows SmartScreen ругается на
   неподписанный exe — «Подробнее → Выполнить в любом случае»; папку
   `C:\Shell1448` добавь в исключения Defender.
6. **Автозапуск**: Планировщик заданий → два задания «При входе в систему»
   (агент, потом киоск, у киоска задержка 10 с). Windows-пользователь
   гостевого ПК — обычный (не админ), автологин.
7. **Service (по желанию, день 2)**: fail-safe блокировка при потере связи.
   В `Service\appsettings.json` секция `Shell`: `BackendWs` и `ComputerId`
   те же, что у агента; установка — PowerShell от администратора:
   `powershell -ExecutionPolicy Bypass -File install-service.ps1`.
8. **kiosk-policies.reg — НЕ применяй в день 1.** Это жёсткий лок Windows
   (диспетчер задач и т.п.); на первый день хватит `kiosk_keys` +
   `exit_password`. Если решишь применить — рядом лежит
   `kiosk-policies-undo.reg` для отката.

## 3. Телефоны гостей

Телефон в Wi-Fi клуба → `http://192.168.1.50:8080/app` («на главный
экран» — станет как приложение). Регистрация — `/register`, но по решению
Р6 гостя логинит админ.

**Подводный камень:** если на точке Wi-Fi включена изоляция клиентов
(AP/client isolation), телефоны не достучатся до ПК-1 — выключи её в
настройках роутера. Проверь это ПЕРВЫМ делом с собственного телефона.

## 4. Смоук-чеклист пилота (прогнать подряд)

1. `/health` с ПК-1 (localhost) и с ПК-2 (`http://192.168.1.50:8080/health`).
2. Киоск на ПК-2 поднялся, индикатор агента горит, сервер — адрес ПК-1.
3. Полный цикл гостя: админ регистрирует гостя → пополняет кошелёк →
   сажает на ПК-2 → на киоске появился «[Готов!]» → гость жмёт → пошло
   время → запуск игры из каталога → завершение → списание и XP видны.
4. Телефон гостя: `/app` → профиль, история сессии.
5. Пакет времени: продать 3 ч → посадить → убедиться, что жгутся минуты
   пакета.
6. Отчёт владельца за сегодня — цифры сходятся с тем, что натыкали.
7. Бэкап руками один раз:
   ```
   docker compose -p 1448club -f docker-compose.club.yml --env-file .env.club exec -T postgres pg_dump -U club1448 1448_db > C:\1448\backup-2026-08-28.sql
   ```

## 5. Откат и удаление

- Остановить: `... down` (данные остаются в volume, `up -d` вернёт всё).
- Снести с данными: `... down -v`.
- Полностью убрать следы с ПК владельца: down -v + удалить `C:\1448`,
  `C:\Shell1448` + деинсталлировать Docker Desktop. Больше система ничего
  на машинах не оставляет.

## 6. Честные оговорки

- **Docker Desktop — самый рискованный шаг**: нужна виртуализация в BIOS и
  перезагрузка. Если на клубных ПК она выключена и пароля BIOS нет — пилот
  сервера в этот день не состоится. Выясни заранее (шаг 0.4).
- Соединение в LAN — HTTP без шифрования. Для пилота в локальной сети это
  приемлемо (наружу порт не торчит, роутер за NAT), HTTPS — отдельный
  спринт. Наружу 8080 не пробрасывать.
- exe киоска и агента не подписаны — SmartScreen/антивирус будут ворчать,
  это ожидаемо (см. 2.5).
- Клубный compose дома прогнать обязательно (шаг 0.1): production-образ
  сегодня целиком прошёл в облаке, но докер-файл клубной связки — новый.
- Если клубный compose на месте почему-то не заведётся — запасной путь:
  поднять как дома (`docker compose up -d --build` с обычным `.env`, режим
  air) и применить миграции руками:
  ```
  docker compose cp backend/migrations postgres:/tmp/m
  docker compose exec postgres sh -c "for f in /tmp/m/*.sql; do psql -U 1448_user -d 1448_db -f $f; done"
  ```
- Диагностика, если что-то не так: `... logs backend --tail 50`,
  `... ps`; с ПК-2 `curl http://192.168.1.50:8080/health` (или в браузере).
  И пиши мне в Claude прямо из клуба — разберём по логам.
