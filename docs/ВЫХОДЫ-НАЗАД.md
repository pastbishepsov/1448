# Выходы: Esc и «назад» на мышке — киоск, калибратор, админка, PWA

2026-09-27. Запрос основателя: «везде (кроме тех мест, где при закрытии нужно сохранить
информацию) должны работать Esc или „назад“ на мышке» — пример: гость в сессии открыл папку
Steam, а обратно в меню можно выйти только стрелкой «← Назад».

## Решения основателя (27.09, молча не переигрывать)

- **Охват — всё:** киоск гостя (`web/shell.html` + AI-калибратор `web/aim.html` в нём),
  админка у стойки (`web/admin.html`), гостевое PWA (`web/app.html` — там это системный
  «назад»: кнопка/жест Android, кнопка браузера).
- **Профиль гостя в киоске:** ничего не менял — Esc / «назад» / клик мимо окна закрывают
  сразу; есть правки — окно «Выйти без сохранения?» с кнопками «Остаться» и «Выйти».
  Кнопка «Отмена» профиля — как раньше (явный отказ от правок, без вопроса).
- **Кейс в киоске:** пока крутится лента — Esc и «назад» ничего не делают; после приза
  «назад» = «Забрать».

## Правило

Одно нажатие — **один шаг назад в самом верхнем видимом слое**, как его видит человек
(больший `z-index`, при равенстве — тот, что ниже в разметке). Кнопки, которые это делают:

| что нажали | киоск | админка | PWA |
|---|---|---|---|
| Esc | да | да | да (на компьютере) |
| боковая кнопка мыши «назад» (XButton1, `button 3`) | да | да | да (на компьютере) |
| клавиша BrowserBack (мультимедийная клавиатура, драйвер мыши) | да | да | да (на компьютере) |
| системный «назад» (Android, жест, кнопка браузера) | — | — | да |

Зажатый Esc не схлопывает всё подряд (`e.repeat` не считается). Кнопка «вперёд» мыши
(`button 4`) просто гасится — чтобы браузер не листал историю.

## Карта выходов

### Киоск (`shell.html`)

| где | что делает Esc / «назад» |
|---|---|
| лок-экран | ничего (это состояние ПК, а не окно) |
| лок → «Правила клуба» | закрыть |
| лок → «Купить пакет» (витрина) | закрыть; подтверждение покупки поверх — «Отмена» |
| витрина: папка платформы / приложений, вкладка «Steam»… | в витрину («Все») |
| витрина: поиск | очистить поиск и снять фокус (папка остаётся — следующий шаг её закроет) |
| шапка: ранги, ⓘ правила, шансы кейсов | закрыть |
| шапка: связь со стойкой (чат) | закрыть панель; набранное сообщение остаётся в поле |
| шапка: профиль | без правок — закрыть; с правками — «Выйти без сохранения?» (Esc на вопросе = «Остаться») |
| общий вопрос-подтверждение (покупка, профиль) | «Отмена» / «Остаться» |
| новый уровень | закрыть |
| кейс | во время ленты — ничего; после приза — «Забрать» |
| AI-калибратор (iframe) | решает сам калибратор, см. ниже |
| итоги сессии | как «Ок» (своё завершение — выход из аккаунта по Р3; внешнее — только закрыть) |
| «Готов?», смена временного пароля, «деньги кончились» | ничего — глухие экраны |
| заставка | гаснет от любого ввода (как было); этот же «назад» больше ничего не делает |
| экран входа | ничего |

### AI-калибратор (`aim.html`, в киоске — iframe)

| где | что делает Esc / «назад» |
|---|---|
| настройки | закрыть калибратор (как ✕) |
| свайп-калибровка поверх настроек | вернуться к настройкам |
| арена без захвата мыши | как ✕ в углу (`exitSession`: от 6 раундов — итог по ним, иначе настройки) |
| арена в захвате мыши | Esc забирает браузер — отпускает захват; «назад» мыши не трогаем (боковые кнопки у игроков часто назначены на своё) |
| итог | закрыть калибратор (как «Закрыть»; «подставить» остаётся в студии сенсы) |
| замер DPI | шаг 1 и 3 — закрыть; шаг 2 без захвата — к шагу 1 |

Фокус может быть и в шелле, и внутри iframe: шелл пересылает «назад» калибратору
(`postMessage {type:'aim_back'}`), тот делает свой шаг и, если надо, отвечает `aim_close`.
Тот же Esc, что отпустил захват мыши, второй раз не считается (400 мс).

### Админка (`admin.html`)

Сверху вниз: тур → палитра (из выбора цели — назад в корень) → выпадашка поиска → колокол →
шторка (сначала её подформа: форма в карточке гостя — пополнение, пакет, XP…, «Проблема» у
ПК, инкассация в «Моей смене»; потом сама шторка) → формы на экране (новый заказ кухни,
компенсация в «Проблемах») → редактор зала (снять выбор ПК, потом выйти) → поле ввода (снять
фокус). На экране входа и когда ничего не открыто «назад» ничего не делает и со страницы не
уводит.

**Несохранённое — со второго нажатия.** Если в закрываемом месте что-то набрано, первое
нажатие только предупреждает тостом «Есть несохранённое — ещё раз Esc или „назад“, чтобы
закрыть без сохранения», второе в течение 4 с закрывает — как arm у кнопок (в админке
`confirm()` нет, решение А3). «Набрано» = значение поля отличается от того, что было в нём
при первом фокусе. Поля, значение которых живёт в переменной (`oninput="x=this.value"` —
вернётся само при следующем открытии, например сумма инкассации или пересчёт кассы), и
выбор файла набранным не считаются.

### PWA (`app.html`)

| где | что делает системный «назад» / Esc / кнопка мыши |
|---|---|
| шторки: бронь, пакеты, пополнение, установка, вход по QR | закрыть |
| кейс | закрыть (как ✕ — в PWA он есть и во время ленты; приз уже начислен и виден в списке) |
| анкета в «Прогрессе» | свернуть; несохранённые правки остаются черновиком и вернутся при «Заполнить» |
| смена временного пароля | ничего — глухой экран |
| ничего не открыто | обычный «назад» телефона/браузера (приложение не держит гостя) |

Почему в PWA кейс и анкета не «спрашивают», как в киоске: см. «Как устроено» ниже — после
системного «назад» нельзя добавить запись истории, не сломав следующий «назад».

## Как устроено

- **Киоск и админка.** Обработчики на `window` в фазе захвата: `keydown` (Escape,
  BrowserBack), `pointerdown`/`mousedown`/`mouseup` для кнопок 3/4. Верхний слой считается по
  факту (`getComputedStyle`: `display`, `z-index`, порядок в DOM), а не по списку открытий —
  что видно, то и закрывается. Проверено на Chromium 141: без `preventDefault` на `mouseup`
  кнопка «назад» мыши листает историю (на демо-стенде уводила из киоска на предыдущую
  страницу); с ним — не листает, а события `pointerdown → mousedown → pointerup → mouseup →
  auxclick` с `button 3` странице приходят. WebView2 — тот же Chromium, в киоске истории нет
  вовсе. C#-оболочку (`shell/`) не трогали: `KeyboardHook` гасит только Alt+Esc и Ctrl+Esc,
  обычный Esc доходит до страницы.
- **PWA.** Окно, открытое касанием, получает одну запись истории (`pushState {g1448:
  глубина}`); системный «назад» её съедает и закрывает верхнее окно; закрыли окно сами (✕,
  тап мимо, «Готово», Esc) — запись снимаем `history.go(-1)`. Синхронизация — через
  `MutationObserver` на классах шторок, открывающие функции не трогались. Правило Chrome
  (History Manipulation Intervention): запись, добавленная без жеста пользователя или сразу
  после системного «назад», помечается «пропускаемой» — следующий «назад» выкидывает из
  приложения. Поэтому запись ставим только при живой активации (`navigator.userActivation`) и
  никогда — между «назад» и следующим касанием; сам «назад» всегда что-то закрывает.
  Попутно: тап по любимой игре в анкете больше не стирает только что набранные
  Discord/Telegram/дату (перерисовка карточки брала значения из профиля). `APP_VER` и
  `app_version` — `2026-09-27.1`.

## Проверка

Скрипты в `tools/e2e` (стенд — как в `tools/e2e/README.md`, playwright-core из той же папки):

```bash
cd tools/e2e
node pw_exits_kiosk.js   # киоск + калибратор: 78 проверок
node pw_exits_pwa.js     # PWA: 26 проверок
node pw_exits_admin.js   # админка: 47 проверок
```

Кнопка «назад» мыши — настоящая: CDP `Input.dispatchMouseEvent` с `button: 'back'` (те же
события, что у гостя), клавиша BrowserBack — `Input.dispatchKeyEvent` (VK 166), системный
«назад» PWA — `page.goBack()`. Гости у проверок свои — `ExitKiosk`, `ExitPwa`, `ExitAdmA`,
`ExitAdmB` (регистрируются сами при первом прогоне; Guest31…Guest50 закреплены за треком З).
ПК: PC-06 (киоск через `?pc=`), PC-02 и PC-07 (админка); заведённая «Проблема» в конце
закрывается, сессии гостя закрываются.

## Не вошло

- Вкладки PWA («Клуб / Кейсы / Прогресс / Чат») «назадом» не переключаются: это не окна;
  «назад» на пустом экране — обычный выход, как у любого приложения.
- На пилотном ПК стоит один раз проверить руками: боковая кнопка мыши и Esc в сессии
  (папка Steam → «назад»), и что драйвер мыши (G HUB / Synapse) не переназначил кнопку.
