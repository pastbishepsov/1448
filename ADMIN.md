## Продуктовые решения (зафиксированы 2026-07-15, внутри спринтов не обсуждаются)

1. **Граница ролей.** Admin = операции смены (сессии, депозиты/начисления
   игрокам, брони, бан игрока, ремонт ПК, журнал дня). Owner = правила игры
   и деньги в динамике (экономика, каталог-конфигурация, схема зала,
   статистика, персонал, полный аудит).
2. **Каталог.** Admin: вкл/выкл и порядок. Owner: создание, правка,
   удаление, `target`/`args` (это конфигурация запуска на гостевых ПК).
3. **Деньги.** Admin видит операции текущего дня с суммами; агрегаты и
   история — owner. Режется на сервере, не в UI.
4. **Серверный инвариант:** цель любого действия персонала — только
   `role=player` и не сам себя. UI-проверок недостаточно.
5. **Бан** = форс-энд активной сессии + лок ПК + событие в ленту.
6. **Лимиты admin** (дневной потолок XP-грантов и депозитов) — в настройках
   owner, 0 = без лимита. Owner лимитами не ограничен.
7. **Гость ↔ админ: чат** (не только кнопка вызова). Вызов админа — частный
   случай сообщения (`kind=call`), работает и без агента.
8. **Канал гостю — поллинг** (`/me/notifications`, `/me/chat`), никакого WS
   в гостевом браузере до после-пилота. Киоск-надёжность важнее мгновенности.
9. **Персонал** — на своём Go+Postgres (users.role), без Supabase.
10. **Каркас навигации — C+A:** рейл двух зон «Смена / Клуб» + поиск,
    колокол и честные KPI в топбаре.
11. **shell.html меняем только в зоне связки:** кнопка «Админ», чат,
    уведомления, обновление баланса. Остальное гостевое — не трогать.

Принципы трека А остаются: один файл `web/admin.html`, ванильный JS; язык
Noir (чёрная база, красный `#ff2740` — единственный акцент, волосяные линии,
без FX-шоу); Phosphor duotone через `data-ic`+`mountIcons()`; частота =
близость; никаких `prompt()`/`confirm()` — drawer и arm-confirm; адаптив;
tabular-nums; каждое действие — в журнал.

## Планировка Б (каркас C + элементы A)

```
┌────────────────────────────────────────────────────────────┐
│ топбар: лого · [поиск «/» гость/ПК] · 🔔 вызовы · live · кто│
├──────────┬─────────────────────────────────┬───────────────┤
│ СМЕНА    │ контент раздела                 │ drawer        │
│ Зал      │                                 │ (ПК / гость / │
│ Гости    │  KPI: Выручка сегодня · В зале  │  форма / чат) │
│ Брони ⑥  │  · Свободно · Броней сегодня    │               │
│ Каталог  │                                 │               │
│ Журнал   │                                 │               │
│ ──────── │                                 │               │
│ КЛУБ     │  (только owner)                 │               │
│ Деньги   │                                 │               │
│ Экономика│                                 │               │
│ Персонал │                                 │               │
│ ──────── │                                 │               │
│ Выйти    │                                 │               │
└──────────┴─────────────────────────────────┴───────────────┘
```

- **Рейл двух зон.** «Смена» видят все; «Клуб» — только owner. Граница прав
  совпадает с навигацией. Бэйдж на «Брони» — брони сегодня; бэйдж на
  колоколе — вызовы/непрочитанные сообщения.
- **Разделы:** Зал (карта + лента + вызовы), Гости, Брони, Каталог
  (admin — тумблеры и порядок; owner — полные формы), Журнал (admin — день,
  owner — всё) · Деньги (бывш. Статистика), Экономика (настройки + лимиты),
  Персонал. Редактор схемы зала — кнопка в Зале (owner), как в А8.
- **Топбар:** глобальный поиск (виден, не только хоткей; «/» фокусирует,
  Enter открывает карточку), колокол с очередью, live-индикатор, имя · роль.
- **Легенда статусов** под картой зала; подсказки хоткеев в title.

## Не делаем (осознанно)

- WS в гостевом браузере — после пилота (поллинг надёжнее в киоске).
- Supabase и любая вторая база/auth — нет; всё на Go+Postgres.
- Переезд на React (`admin/`) — нет; один файл — сила пилота.
- Платежи/Stripe — спринт 6 основного трека.
- Роли тоньше admin/owner (смены, кассиры) — после пилота.
- Push каталога на гостевые экраны — агентского polling ≤5 мин хватает.
